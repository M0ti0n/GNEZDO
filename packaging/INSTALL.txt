GNEZDO - TEST BUILD FOR WINDOWS
===============================

Nothing has to be installed: the "program" folder contains everything GNEZDO needs.
Start it with start.bat; settings are in config.json next to it.


1. COPY GNEZDO TO THE PC
------------------------
1. Download gnezdo-server-windows.zip (link in the README on GitHub, "Download").
2. Right-click -> Extract All... -> Extract.
   You get a folder "gnezdo", e.g. C:\Users\<name>\Desktop\gnezdo


2. START GNEZDO
---------------
1. Open the "gnezdo" folder and double-click start.bat.
2. The first time Windows may say "Windows protected your PC" (the program is
   not signed): click "More info" -> "Run anyway".
   If the firewall asks, allow it on private networks (needed for other PCs).
3. A black window opens and the browser opens http://localhost:8090
   Leave the black window open; closing it stops GNEZDO.
   Other PCs on the network use  http://<name-of-this-pc>:8090


NESTING: the "nesting" folder next to "program" holds the nesting engine
(PackingSolver and a Python of its own). Keep the two folders together; nothing
else has to be installed.


3. THE DATABASE
---------------
GNEZDO keeps parts, jobs and settings in a Microsoft SQL Server database
(Express is enough). It uses its OWN database (called "gnezdo" unless you
choose another name) and creates it itself. Never point it at the database of
another program (an ERP, other nesting software): GNEZDO refuses a database that
belongs to another program.

The first time GNEZDO starts, the browser shows "Set up the database":
1. SQL Server: the server name, e.g. SERVERNAME\SQLEXPRESS (or SERVERNAME,1433).
2. Database: gnezdo.
3. Sign-in: Windows sign-in (the Windows user GNEZDO runs as), or an SQL login
   with its password. The login needs rights to create a database the first time.
4. "Test connection", then "Save and continue". GNEZDO writes it into config.json,
   creates the tables, and asks for the first admin (see 7).

Later an admin can point GNEZDO at another database: Settings -> Data -> Change
(used after GNEZDO is started again). Or edit "Gnezdo" under ConnectionStrings in
config.json while GNEZDO is stopped.

THE DEMO: to try GNEZDO without a database (sample parts and jobs, nothing is
saved), set "Setup": false under "Gnezdo" in config.json and leave the
connection empty, then start GNEZDO again.


4. A NEWER VERSION
------------------
Extract the new zip over the old folder. Your config.json is kept (the zip only
has config.example.json). The database updates itself on the first start.


5. "ACCESS DENIED" OR "BLOCKED" ON A COMPANY PC
-----------------------------------------------
start.bat first checks whether this PC lets GNEZDO.exe run. When it does not
("Access is denied"), it starts the DEMO with Python instead (the same Python
KOSOVNICE uses): all import tools work in the browser, nothing is saved.

To run the real GNEZDO.exe on such a PC, try in this order:
1. The download block: right-click program\GNEZDO.exe -> Properties. If there is
   an "Unblock" tick box at the bottom, tick it -> OK, and start start.bat again.
   (Or before unzipping: right-click the zip -> Properties -> Unblock.)
2. Company rules (AppLocker / "blocked by your system administrator"): programs
   may only run from approved folders. Ask IT to allow the GNEZDO folder, or run
   GNEZDO on the server where it will live anyway.

Other messages:
- In the black window "GNEZDO could not start ... port ...": another program
  uses port 8090 or it is reserved on this PC. Open config.json, change 8090 in
  "Urls" to another number (e.g. 8091), start again and open
  http://localhost:8091 instead.
- The browser says it cannot reach the page: wait a few seconds after the black
  window shows "Open http://localhost:8090" and refresh.


6. DIAGNOSTIC LOG
-----------------
GNEZDO writes down what happens (nests and how they ended, saves, tools used,
errors, with who and when) in the "logs" folder next to config.json, one file
a day, kept 30 days (at most 200 MB). When something goes wrong:
1. GNEZDO menu -> Settings -> Diagnostic log -> "Report a problem": a few words
   about what went wrong (it marks the moment in the log).
2. "Download log" there gives a zip of the last days: send that.
It can be switched off there, for everyone on this server. Job, part and user
names are in it; drawings are not. It never leaves the server by itself.


7. USERS AND SIGN-IN (with the database)
----------------------------------------
With a database, GNEZDO asks everyone to sign in. On the very first start it
asks for the first user, who is an admin. The admin adds the others: click your
name in the top right -> Users. A password is optional; without one, anyone who
knows the name can sign in as that user, so give admins a password.
Only an admin can change the machines and switch the diagnostic log on or off.
Everyone can set or change their own password (click your name).
A sign-in lasts 30 days in that browser. The keys for it are in the "data"
folder next to config.json: keep that folder when updating.
The demo (no database) has no sign-in.
